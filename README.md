# Meta-Introspector Project Documentation

This repository contains the source code and documentation for the Meta-Introspector project. Our goal is to consolidate and provide comprehensive, easily accessible documentation for all aspects of the project.

## Documentation Status

We are currently in the process of setting up a centralized documentation portal.

### General Project Documentation (Markdown & Text Files)

All general project documentation, including architectural overviews, research findings, deployment notes, and guides (originally in various Markdown and text files), has been moved into the `docs/` directory.

A static documentation website is being set up using **MkDocs** and the `mkdocs-material` theme. This website will be published to GitHub Pages, providing a searchable and navigable interface for our non-code-specific documentation.

### Rust Code API Documentation (Rustdoc)

We are working to integrate the official Rust API documentation generated by `rustdoc` into our documentation portal. However, there are currently several **blocking compilation errors** in the Rust codebase that prevent `rustdoc` from successfully generating output.

**Current Challenges with `rustdoc` Integration:**

The `cargo doc` command is failing due to issues within the Rust source files. These include:

*   **Binaries used as Libraries**: Some `.rs` files are defined as `[[bin]]` targets in `Cargo.toml` but are being imported and used as `crate::` modules by other `.rs` files. Rust's module system does not allow a binary target to be imported directly as a library by another binary within the same package. This requires refactoring certain binaries into `[[lib]]` crates or moving shared logic to a `src/lib.rs`.
*   **Duplicate Function/Struct Definitions**: Conflicts where the same function or struct (`CallStat`, `count_all_isomorphisms`, `compute_eigenvalues`) is defined multiple times within the same module, leading to `E0428` and `E0119` errors.
*   **Missing Dependencies**: While many missing dependencies have been identified and added to `Cargo.toml`, some remain due to incorrect import paths or undeclared `[[lib]]` crates.
*   **Undefined Macros**: Custom macros (`mkbootstrap!`, `telemetry_wrap!`, `demo!`, `production!`) are being invoked but are not found in scope, indicating either missing macro definitions or incorrect import paths/crate configurations.
*   **Syntax Errors**: Specific syntax errors in generated or experimental code (e.g., `semantic_rust_compressor.rs`, inline assembly in `universal_wrapper.rs`) also prevent compilation.

**Next Steps Required for `rustdoc` Integration:**

To successfully generate and integrate `rustdoc` output, these compilation errors in the Rust source code must be resolved. **This will require direct modifications to the `.rs` source files.** We need to decide how to proceed with these modifications:

*   **Option A (Recommended)**: Allow the documentation agent to make minimal, targeted changes to the `.rs` files to resolve these compilation errors and enable `cargo doc`. These changes will be clearly communicated.
*   **Option B**: Provide specific instructions on how you (the user) would like to fix each compilation error (e.g., refactor binaries into libraries, explicitly define missing macros, remove duplicate code).

Your guidance on resolving these code-level issues is needed to fully enable `rustdoc` integration.

## How to Access Documentation

*   **Static Site (MkDocs)**: Once deployed to GitHub Pages, the general project documentation will be accessible via: `https://meta-introspector.github.io/`
*   **Rustdoc (Local)**: After the compilation errors are resolved, you can generate `rustdoc` locally by running `cargo doc`. The output will be in `target/doc/`.

## Contributing to Documentation

Please add new documentation files to the `docs/` directory. For Rust code, ensure you use `///` and `//!` doc comments following Rust's documentation conventions.
